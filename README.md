# 드론 지휘관 (가제)

드론을 지휘하는 사이버펑크 서바이벌 액션 게임 · 신입 게임기획 포트폴리오

> 이 문서는 Unity나 게임 개발을 잘 모르는 사람도 이해할 수 있도록, 어려운 용어가 나올 때마다 짧게 풀어서 설명합니다.

## 게임 소개

| 항목 | 내용 |
|---|---|
| 장르 | 생존 액션 (이동과 성장 중심의 서바이벌 액션) |
| 배경 | 사이버펑크·SF, 로봇이 도시를 장악한 근미래 |
| 그래픽 | 3D (쿼터뷰 시점 — 캐릭터를 비스듬히 위에서 내려다보는 각도. 예: 디아블로 같은 게임의 시점) |
| 플랫폼 | PC (itch.io 배포 예정 — itch.io는 인디 게임을 무료/저가로 올려 배포하는 사이트) |
| 개발 기간 | 1~2개월, 1인 개발 |
| 개발 환경 | Unity(게임을 만드는 프로그램) + Claude(AI 코딩 도우미), 3D 모델은 VARCO 3D 제작·에셋스토어 구매 병행, Blender(3D 모델 편집 프로그램)로 다듬음 |
| 형상 관리 | GitHub (코드 변경 이력을 저장하고 되돌릴 수 있게 관리하는 서비스) |

주인공은 로봇이 도시를 장악한 근미래 세계의 엔지니어다. 직접 싸우는 대신, 자신을 따라다니는 여러 대의 드론을 통해 싸운다. **플레이어는 이동만 담당**하고, 공격은 드론들이 자동으로 처리한다.

핵심 재미는 시간이 지나며 얻는 드론들을 **어떤 조합으로 키워나가는가**에 있다. 같은 시작이라도 어떤 드론을 먼저 얻고 어떻게 강화하는지에 따라 매판 다른 전략이 만들어지도록 설계했다.

## 조작법

| 입력 | 동작 |
|---|---|
| WASD / 방향키 / 게임패드 왼쪽 스틱 | 이동 |
| **스페이스바** | **오버드라이브 발동** (게이지가 가득 찼을 때만) |
| **P** | 일시정지 메뉴 열기/닫기 (계속하기/재시작/메인메뉴) |
| (없음) | 평소 공격은 드론이 자동으로 수행 |

## 기본 진행 방식

- 한 판에서 로봇은 **10분 동안** 나온다. 10분이 지나면 새 로봇은 더 나오지 않고, **남아 있는 로봇을 모두 처치하면** 승리로 종료된다. (남은 로봇이 많으면 10분보다 조금 더 걸린다. 화면 위쪽 시간 표시는 10분이 지나면 "남은 적 n"으로 바뀐다.)
- 시간이 지날수록 로봇이 더 많이, 더 강하게 등장한다 (아래 "적 시스템" 표 참고).
- **미니 보스**: 한 판 도중 **3분**과 **6분**에 중간 보스가 한 마리씩 나온다. 나올 때 화면 위쪽에 "미니 보스 출현!" 알림이 뜨고, **처치하면 레벨업 때와 같은 3택1 선택지(드론 추가·강화 등)를 한 번 더 받는다.** (아직 전용 모델이 없어서 보스 모델을 작게 줄여 주황색으로 칠한 임시 모습이다.)
- **마일스톤**(중간 목표 보상): 판 도중 정해진 시간에 도달하면 코어(뽑기에 쓰는 재화)를 준다. **3분 도달 +100 / 6분 도달 +150 / 처음 클리어 +200**이고, 각각 **스테이지마다 따로 딱 한 번씩** 받는다. (스테이지 1에서 받았어도 스테이지 2·3에서 다시 달성하면 또 받을 수 있고, 같은 스테이지에서는 이미 받은 뒤에 다시 해도 안 나온다. 스테이지가 오를수록 보상이 늘어난다: 스테이지 1은 3분 +100 / 6분 +150 / 처음 클리어 +200, 스테이지 2는 3분 +200 / 6분 +300 / 처음 클리어 +400, 스테이지 3은 3분 +300 / 6분 +450 / 처음 클리어 +600.) 판에서 목표를 달성하면 화면 위쪽에 "스테이지 1 마일스톤 3분 달성! 로비에서 코어 +100을 받을 수 있어요"처럼 알림이 뜨고, 코어는 **로비의 "마일스톤" 창**(오른쪽 아래 버튼)에서 스테이지를 고른 뒤 3분 / 6분 / 클리어 칸을 골라 **"획득"을 눌러야** 들어온다. (일일 퀘스트와 같은 방식이라, 자동으로 들어오지 않는다.)
- **일일 퀘스트**: 로비 오른쪽 아래 "일일 퀘스트" 버튼으로 연다. **출석하기 +200 / 3분 버티기 +50 / 6분 버티기 +100 / 클리어하기 +150** 코어이다(하루에 모두 받으면 500, 창에서는 출석하기가 맨 위에 보인다). 앞의 셋은 한 판에서 조건을 채우면, **출석하기는 그날 처음 로비에 들어오면** 자동으로 "달성" 표시가 되며, 창에서 **"받기" 버튼을 눌러야** 코어가 들어온다. 하루(기기 날짜 기준)가 지나면 모두 같은 시각에 초기화돼서 매일 다시 할 수 있다.
- **XP**(경험치, Experience Point의 줄임말)를 모으면 **레벨업**한다. 로봇을 처치하면 그 자리에 XP 구슬이 떨어지고, 플레이어가 가까이 가면 자동으로 흡수된다. 레벨업할 때마다 3개 선택지 중 하나를 골라 드론을 늘리거나 강화하거나, 능력치를 올린다.
- 화면 위에는 항상 **HUD**(Head-Up Display — 체력/시간처럼 지금 상태를 알려주는 화면 표시)가 떠 있어서, 체력바·XP바·오버드라이브 게이지·레벨·남은 시간을 바로 확인할 수 있다.

## 오버드라이브 — 이 게임의 유일한 액티브 스킬

플레이어가 직접 누르는 버튼은 이것 하나뿐이다.

- 로봇을 처치할 때마다 **오버드라이브 게이지**가 찬다 (엘리트 로봇은 한 마리로 일반 로봇 약 6마리분을 채워준다).
- 게이지가 가득 차면 **스페이스바**로 발동 — 5초 동안 모든 공격 드론의 공격 속도가 **2.5배**가 되고, 이동 속도도 25% 빨라진다.
- **단, 그 5초 동안은 내가 받는 피해도 2배가 된다.**

**왜 이렇게 설계했나 (기획 의도)**

원래 이 게임은 "플레이어는 이동만, 공격은 드론이 자동"이라는 구조였다. 그런데 실제로 만들어놓고 보니 한 판 10분 동안 플레이어가 내리는 판단이 *이동 방향*과 *레벨업 3택1*밖에 없어서, 그 사이의 순간순간이 밋밋했다.

그래서 "지금 쓸까, 참을까"라는 판단을 하나 심었다. 핵심은 **피해 2배라는 대가**다:

- 게이지는 처치로만 차기 때문에, **적이 많이 몰린 순간 = 게이지가 빨리 차고 발동 이득도 큰 순간**이다.
- 그런데 적이 많이 몰린 순간은 동시에 **가장 위험한 순간**이기도 하다.
- 결국 "이득이 가장 클 때가 가장 위험할 때"가 되어, 발동 타이밍 자체가 매번 다른 선택이 된다.

회복 드론만은 이 배율에서 일부러 제외했다. 회복까지 빨라지면 "위험을 감수한다"는 전제가 무너지기 때문이다.

화면에서는 발동 중 가장자리가 주황색으로 맥동한다. (빨강=죽기 직전 경고, 주황=내가 선택한 위험, 시안=안전/성장 — 색으로 상황을 구분할 수 있게 나눠뒀다)

### 엘리트 로봇

일반 로봇 중 일부가 **엘리트**로 등장한다 (30초 이후, 8% 확률).

| 항목 | 일반 대비 |
|---|---|
| 체력 | 3배 |
| 크기 | 1.35배 (한눈에 구분됨) |
| 색 | 시안색으로 물듦 |
| 주는 XP | 3배 |
| 오버드라이브 게이지 | 약 6배 |
| 부딪힐 때 피해 | **동일** (일부러 안 올림) |

부딪힐 때 피해를 안 올린 이유: 엘리트를 "더 아픈 적"이 아니라 "잡는 데 오래 걸리지만 보상이 큰 적"으로 만들어야, 플레이어가 피하지 않고 **노리게** 되기 때문이다. 덕분에 "저놈부터 잡을까?"라는 우선순위 판단이 생긴다.

오버드라이브와도 맞물린다 — 엘리트를 잡으면 오버드라이브가 빨리 차고, 오버드라이브 중에는 엘리트를 잡기 쉬워진다.

## 드론 시스템

드론은 최대 5~6개까지 동시에 보유할 수 있으며, 게임 시작 시 근접 드론 하나만 가지고 출발한다. 드론 하나는 5단계까지 강화할 수 있고, 5단계에 도달하면 상위 형태로 변신한다.

| 드론 | 역할 | 강화 시 좋아지는 것 |
|---|---|---|
| 근접 드론 | 주인공 주위를 돌며 가까운 적 공격 | 도는 속도 또는 크기 |
| 저격 드론 | 가장 가까이 있는 적을 원거리 공격 | 공격력 또는 공격 속도 |
| 폭발 드론 | 일정 시간마다 주변 전체에 범위 피해 | 폭발 범위 또는 피해량 |
| 회복 드론 | 주인공 체력을 서서히 회복 | 회복량 또는 회복 주기 |
| 수집 드론 | 아이템·경험치를 자동으로 끌어모음 | 끌어당기는 범위 |

## 적 시스템 — 폭주한 보안 로봇

| 로봇 종류 | 체력 | 이동 속도 | 부딪힐 때 피해 | 처음 등장 시점 |
|---|---|---|---|---|
| 약한 로봇 | 14 | 보통 | 6 | 시작부터 |
| 튼튼한 로봇 | 38 | 느림 | 10 | 1분 30초부터 |
| 빠른 로봇 | 8 | 빠름 | 6 | 1분 30초부터 |
| 강한 로봇 | 95 | 느림 | 18 | 6분째부터 |
| 보스 로봇 | 500 | 매우 느림 | 25 | 9분째, 한 번만 |

로봇이 나오는 10분을 세 구간(처음 1분 30초 / 중간 4분 30초 / 마지막 4분)으로 나누어, 로봇 등장 속도와 최대 동시 등장 수가 달라진다. (이렇게 시간에 따라 점점 어려워지게 짜놓은 것을 "난이도 곡선"이라고 부른다.)

**미니 보스**는 위 표의 5종과 별개로 3분·6분에 한 번씩 나온다. 보스 로봇의 모습을 60% 크기로 줄인 임시 모델을 쓰고, 체력은 보스(500)의 **50%(3분) / 80%(6분)**다. (이 배율은 `EnemySpawner.cs`의 `miniBossHealthMultipliers`에서 바꾼다.)

**건물(기둥)과 적 (2026-10-05)**: 경기장에는 건물 5개가 서 있다. 원래는 **플레이어만 건물에 막히고 적은 통과**했는데, 적의 이동 코드가 물리 충돌을 보지 않고 위치를 직접 옮기는 방식이라서 그랬다. 지금은 적도 건물을 통과하지 못한다. 적이 플레이어에게 걸어가다가 건물이 사이를 가로막고 있으면 플레이어 대신 **건물의 모서리를 향해 걷고**(두 모서리 중 돌아가는 길이 더 짧은 쪽), 모서리를 지나면 다시 플레이어를 향해 곧장 걷는다. 건물 안에서 태어난 적은 가장 가까운 면 바깥으로 밀려 나온다. 물리 엔진을 쓰지 않고 계산만 해서 웹(WebGL)에서도 가볍다. 건물에 `EnemyObstacle` 스크립트가 붙어 있고, 크기와 위치는 건물의 `BoxCollider`에서 읽으므로 건물을 옮기거나 새로 만들 때 코드를 고칠 필요가 없다(새 건물에는 이 스크립트만 붙이면 된다). 이제 플레이어가 건물 뒤로 돌아서 적을 모는 플레이가 가능하다.

## 프로젝트 구조

Unity 프로젝트는 보통 이런 폴더들로 이루어진다. 각각이 뭘 하는 폴더인지 처음 보면 낯설 수 있어서 간단히 설명을 붙였다.

```
Assets/                    (게임에 쓰이는 모든 것이 들어있는 폴더)
├── Scripts/               (게임 동작을 정의하는 C# 코드 파일들)
│   ├── Core/                게임 공용 시스템 (체력, 이벤트, 매치 타이머)
│   ├── Player/               플레이어 이동, 능력치, 경험치, 오버드라이브(액티브 스킬)
│   ├── CameraControl/         쿼터뷰 카메라 추적
│   ├── Enemies/              적 데이터/AI(적 스스로 움직이고 공격하는 로직)/스폰(적을 생성하는 것)
│   ├── Drones/               드론 5종 + 드론을 관리하는 매니저
│   ├── Pickups/              XP 오브(구슬), 자석처럼 끌어당기는 범위
│   ├── LevelUp/              레벨업 3택1 선택지 UI
│   ├── UI/                   HUD, 결과 화면, 메인 메뉴/설정 (HUD 위쪽 알림 문구 HUDNotice 포함)
│   │   ├── Lobby/              로비 화면과 스테이지 선택 화면
│   │   ├── Gacha/              뽑기 화면, 뽑기 결과 화면, 확률 공개 팝업, 등급 색
│   │   └── Hangar/             격납고 화면 (드론 목록·강화·장착)
│   ├── Meta/                 "판과 판 사이"의 시스템(테스트 기록 PlayLog, 웹 브라우저 연결 BrowserBridge 포함): 뽑기(GachaSystem), 재화(CurrencyManager),
│   │                           저장(SaveData/SaveManager), 스테이지 해금·선택(StageProgress),
│   │                           보유 드론·강화·장착·전투력(DroneInventory),
│   │                           뽑기 전체 흐름 연결(GachaController), 마일스톤 수치(MatchMilestones), 일일 퀘스트(DailyQuests)
│   └── Editor/               유니티 에디터에서만 쓰이는 개발 도구 스크립트 (실제 빌드엔 안 들어감)
│                           (예: Play 버튼을 누르면 항상 메인메뉴부터 시작하게 해주는 스크립트,
│                            뽑기·재화·스테이지가 규칙대로 동작하는지 확인하는 검증 도구, 로비 씬 생성 도구)
├── Data/Enemies/           적 5종의 수치(체력·속도 등)를 담은 데이터 파일
├── Plugins/WebGL/          웹(WebGL) 빌드에서만 쓰이는 자바스크립트 함수 (테스트 기록 복사·파일 저장)
├── Data/Meta/              뽑기 확률·비용·중복 조각(GachaTable), 재화 보상(CurrencyTable), 스테이지 3개(StageData_01~03),
│                           드론 등급 배율·강화 비용(DroneGrowthTable) 수치 파일
│                           (코드를 고치지 않고도 수치만 따로 바꿀 수 있게 분리해둔 것 —
│                            Unity에서는 이런 데이터 파일을 "ScriptableObject"라고 부른다)
├── Prefabs/                드론 5종, 적 5종, XP 오브의 "완성된 틀"
│                           (프리팹 = 미리 조립해둔 오브젝트 설계도. 하나 만들어두면
│                            게임 중에 필요할 때마다 똑같은 걸 계속 찍어낼 수 있다)
├── Models/                 실제 3D 모델 파일(fbx)과 그 텍스처(표면 이미지)·머티리얼
│   ├── Player/               주인공 모델
│   ├── Drones/               드론 5종 모델 (Melee/Sniper/Collector/Explosion/Heal 폴더로 분리)
│   └── Enemies/              적 5종 모델 (Weak/Tough/Fast/Strong/Boss 폴더로 분리)
│                           (같은 이름의 파일(diffuse.png 등)이 섞이지 않도록 종류별로 폴더를 나눠둠)
├── Materials/              오브젝트 표면 색/질감을 정하는 파일들 (일부는 여전히 단색 플레이스홀더)
├── Audio/                  소리 파일들
│   ├── Music/                 배경음악(BGM, loop 재생)
│   └── SFX/                   효과음(Sound FX) — 피격/사망/레벨업/오버드라이브 등
├── Fonts/                  Geist / Geist Mono 폰트 파일 (영문 UI에 사용)
├── UI/                     UI에 쓰이는 이미지 (체력바/XP바용 흰색 채우기, 배경 격자무늬 등)
└── Scenes/                 씬 = 하나의 "화면 세트" (예: 메뉴 화면, 실제 플레이 화면)
    ├── MainMenu.unity         시작 화면 (게임 시작/조작법/게임 설명/설정)
    ├── Lobby.unity            로비 (재화 확인, 스테이지 고르기, 출격, 뽑기·격납고 화면으로 이동)
    ├── Gacha.unity            뽑기 화면 (1회/10연, 천장 게이지, 확률 보기, 뽑기 결과 연출)
    ├── Hangar.unity           격납고 (가진 드론 보기, 강화, 출격 장착)
    └── InGame.unity           실제 플레이 씬 (예전 이름: SampleScene)
```

메인 메뉴에서 "게임 시작"을 누르면 `Lobby`(로비) 씬으로 간다. 로비에서 스테이지를 고르고 "출격"을 누르면 `InGame` 씬이 시작된다. "조작법"/"게임 설명"은 같은 화면 위에 뜨는 팝업이고, "설정"에는 마스터 볼륨 슬라이더(0~200%, 원본 음원이 작을 때도 증폭해서 들을 수 있게 범위를 넓힘)가 있으며 PlayerPrefs(설정값을 컴퓨터에 저장해두는 Unity 기능)에 저장되어 다음 실행에도 유지된다. 전체화면 토글은 제거했다(항상 창 모드로 실행).

- **판 사이의 메타 루프 만들기 시작 (2026-09-30)**: "판이 끝나면 재화를 얻고 → 뽑기로 드론을 얻어 → 더 강한 스테이지에 도전"하는 흐름(메타 루프 = 한 판 밖에서 도는 성장 순환)을 붙이는 작업을 시작했다. 지금까지 끝낸 것:
  - **뽑기 로직** `GachaSystem`: 등급 확률(N 55% / R 30% / SR 12.5% / SSR 2.5%), 1회 300코어 / 10연 2,700코어, **천장 70회**(70번째 뽑기에서 SSR 확정, 화면 밖 검증에서 500만 번 뽑았을 때 SSR 1개당 평균 33.19회로 기획 수치 33.2와 일치)
  - **재화와 저장**: 코어(유료 재화)·크레딧(플레이로 버는 재화)을 관리하고 `save.json` 파일에 저장해서 다음 실행에도 유지. 처음 시작하면 코어 2,700을 준다
  - **로비 화면과 스테이지 선택**: 메인 메뉴 → 로비 → 출격 흐름. 스테이지는 3개이고 앞 스테이지를 클리어해야 다음이 열리며, 최고 생존 시간을 기록한다. 스테이지가 올라갈수록 적의 체력·접촉 피해에 배율이 곱해진다(아래 밸런스 표 참고)
  - **보유 드론 관리** `DroneInventory`: 뽑은 드론을 내 목록에 반영한다. 드론은 종류당 1개만 가지고, 이미 가진 드론이 또 나오면 → 더 높은 등급이면 **승급**(강화 레벨은 유지), 같거나 낮은 등급이면 **조각**(설계도 조각, 강화 재료)으로 바뀐다. 조각과 크레딧으로 드론을 최대 레벨 5까지 강화할 수 있고, 출격용 슬롯 2개에 드론을 장착한다. 처음 시작하면 근접 N + 저격 N 드론을 준다
  - **전투력**: 장착한 드론의 등급·레벨을 합친 수치(시작 상태 100). 로비의 스테이지 카드에 권장 전투력과 나란히 보이며, 권장 이상이면 초록 / 70~100%면 주황 / 70% 미만이면 빨강으로 표시된다
  - **뽑기 전체 흐름** `GachaController`: 화면이 "1회 뽑기"나 "10연 뽑기"를 요청하면 ① 코어를 먼저 내고 ② 뽑고 ③ 결과를 내 드론 목록에 반영하고 ④ 천장 횟수를 저장하는 순서를 한 곳에서 처리한다. 코어가 모자라면 아무것도 차감하지 않고 "부족" 알림만 보낸다. 천장 횟수도 저장해서 게임을 껐다 켜도 이어진다. 뽑을 때마다 콘솔에 "몇 회 뽑기 완료: 등급별 개수 · 신규 · 승급 · 조각 · 코어 잔액 · 천장" 한 줄이 남아서 나중에 테스트 기록으로 쓸 수 있다
  - **뽑기 화면** `Gacha` 씬: 로비의 "뽑기" 버튼으로 들어간다. 배너, 등급별 확률 요약, **천장 게이지**("SSR 확정까지 누적 n / 70" + 채워지는 막대), 1회(300코어)·10연(2,700코어, 10% 할인 뱃지) 버튼, 코어 잔액이 있다. 코어가 모자라면 가격 글자만 빨갛게 바뀌고, 눌러 보면 "코어가 부족합니다" 팝업이 뜬다. "확률 보기"를 누르면 확률 공개 팝업이 열려 등급별 확률과 천장·초기화·10연 규칙을 문장으로 보여준다. **화면에 적힌 확률·가격·천장 횟수는 전부 뽑기 로직이 쓰는 데이터 파일(`GachaTable`)에서 그대로 읽어온다** — 표기용 숫자를 따로 적지 않으므로 표기와 실제가 어긋날 수 없다
  - **뽑기 결과 화면**: 뽑기를 하면 카드 뒷면("?")이 먼저 깔리고, 카드를 한 장씩 순서대로 뒤집으며 공개한다. 공개 시간은 등급이 높을수록 길어서(N 0.4초 / R 0.6초 / SR 1.0초 / SSR 2.0초) 기다리는 동안 카드 테두리가 그 등급 색으로 반짝이고, SSR이 나오는 순간 화면이 금색으로 번쩍인다. 카드마다 **NEW**(처음 얻은 드론) / **승급 N → R**(같은 드론이 더 높은 등급으로 나옴) / **중복 조각 +10**(같거나 낮은 등급이라 조각이 됨)이 표시된다. 우상단 **스킵**을 누르면 언제든 남은 카드를 한 번에 공개하고(반복 뽑기가 지루하지 않게), 다 공개되면 **확인**(닫기)과 **다시 뽑기**(같은 방식으로 한 번 더, 코어가 모자라면 눌리지 않음) 버튼이 나온다
  - **격납고 화면** `Hangar` 씬: 로비의 "격납고" 버튼으로 들어간다. 왼쪽에 드론 5종 목록(등급·레벨, 장착 중 표시, 아직 못 얻은 드론은 흐리게 "미획득")이 있고, 하나를 고르면 오른쪽에 상세가 나온다: 전투력, 성능 배율(등급 배율 × 강화 배율로 나눠서 표시), **조각 진행바**(예: 조각 12 / 30), 필요한 크레딧, **강화 버튼**. 조각이나 크레딧이 모자라도 버튼을 눌러 보면 무엇이 부족한지 안내해 준다. 아래쪽 **출격 슬롯 2개**에서 드론을 골라 장착할 수 있다(이미 다른 슬롯에 있는 드론을 끼우면 서로 자리가 바뀌고, 같은 슬롯을 다시 누르면 해제). 장착이 바뀌면 "내 전투력"이 바로 갱신되고 로비에도 반영된다
  - **판 종료 보상과 결과 화면**: 판이 끝나면(클리어든 실패든) 재화를 지급한다. 판 보상은 **크레딧만** 준다. 클리어하면 스테이지마다 달라서 크레딧 스테이지 1 +200 / 스테이지 2 +300 / 스테이지 3 +400이고, 코어는 클리어해도 주지 않는다(클리어에 대한 코어 보상은 마일스톤의 "처음 클리어"가 대신한다). 실패해도 **크레딧만** 받는다. 코어는 마일스톤과 일일 퀘스트로만 얻는다. 크레딧에도 조건이 있다: 생존 시간이 **1분 미만이면 보상이 없고**(일부러 금방 죽어서 재화를 모으는 것을 막기 위해), 1분을 넘긴 뒤부터는 버틴 시간에 **비례**해서 받는다(1분 → 0, 로봇이 나오는 10분을 다 버티면 클리어 크레딧과 같아지는 직선). 예: 스테이지 1에서 5분 30초까지 버티고 죽으면 코어 +0 / 크레딧 +100이다. 일찍 져서 보상이 0이면 결과 화면에 "1분 이상 버텨야 보상을 받을 수 있어요"라는 안내가 나온다. 결과 화면(GAME CLEAR / GAME OVER)에는 생존 시간 아래에 **획득 보상** 영역이 생겼고, 코어·크레딧 숫자가 0에서부터 약 0.8초 동안 올라가는 연출로 보여준다. 버튼은 **로비로**(방금 얻은 재화가 반영된 로비로 이동)와 **재도전**(같은 스테이지를 처음부터 다시)이다. 클리어하면 다음 스테이지가 열린다
  - **장착한 드론으로 판 시작**: 이제 격납고에서 장착한 드론 2개를 들고 판을 시작한다(처음 시작하면 근접 N + 저격 N). 그 드론들에는 뽑기 **등급 배율 × 강화 배율**(예: 근접 SR ×1.25, 회복 SSR ×1.45)이 곱해진다. 배율은 판 안 레벨업(레벨당 +16%)과 같은 능력치 전부에 곱해진다 — 근접은 회전 속도·공격 범위, 저격은 피해량·공격 속도, 폭발은 피해량·범위, 회복은 회복 빈도, 수집은 자석 범위. 장착하지 않은 드론이나 레벨업 선택지로 새로 얻는 드론은 ×1.0이다. 이제 "플레이 → 뽑기 → 장착 → 다시 플레이" 한 바퀴가 실제로 돈다
  - **웹(WebGL) 빌드 대비 저장 동기화 (2026-09-30)**: 웹 게임은 진짜 하드디스크가 없어서 `save.json`이 먼저 메모리 안의 가짜 파일로 써지고, 그 내용이 브라우저 저장소로 옮겨져야 새로고침 후에도 남는다. 이 "옮기기"는 자동이 아니라서, 저장할 때마다 유니티 웹 플레이어의 `JS_FileSystem_Sync` 함수를 부르도록 `WebGLFileSync`를 추가했다(PC·에디터에서는 아무 일도 하지 않음). 볼륨 설정도 설정 패널을 닫을 때 `PlayerPrefs.Save()`로 한 번 저장한다. 실제 웹 빌드에서 새로고침 후 저장이 남는지는 빌드로 확인해야 한다. 웹 빌드 압축 설정도 itch.io에서 안전한 **Gzip + 압축 해제 대체(Decompression Fallback) 켜기**로 바꿨다(기존 Brotli, 대체 꺼짐 — itch.io는 서버 설정을 직접 바꿀 수 없어서 브라우저에 따라 게임이 안 뜰 수 있음)
  - **테스트(CBT) 기록 수집 (2026-09-30)**: 웹 게임은 테스터의 브라우저 안에만 파일이 생겨서 개발자가 기록을 받을 수 없다. 그래서 게임이 스스로 플레이 기록을 쌓고, 테스터가 로비의 **"테스트 로그"** 창에서 **복사**하거나 **파일로 저장**해서 보내게 했다. 기록에는 게임을 켠 시각, 화면 이동(마지막에 본 화면 = 이탈 지점), 뽑기 결과와 코어 수지, 판 결과(스테이지·클리어 여부·생존 시간·도달 레벨·받은 보상), 강화·장착, 스테이지 해금이 들어가고, 맨 위에는 **요약**(판 수, 클리어율, 판당 평균 보상, 뽑기 횟수, SSR 개수, 첫 뽑기 전에 몇 판 했는지 등)이 자동으로 붙는다. 요약에는 **실패한 판 평균 생존 시간**(게임 시간 기준)과 **판당 평균 실제 소요 시간**(일시정지·레벨업 선택 화면 포함, 클리어한 판만 따로도 표시)도 들어가서 한 판이 실제로 몇 분인지 판단하는 근거가 된다. 이 요약과 기록이 시뮬레이터 가정값(클리어율 40/50/60%, 판당 코어 등)을 실제 플레이로 보정하는 근거가 된다. 개인정보는 남기지 않고, 테스터는 임의의 6자리 번호로만 구분한다. 복사 버튼이 브라우저에서 막히면 파일 저장을 쓰면 된다. **정식 출시 전에는 이 버튼을 숨길 예정**이다
  - **마일스톤·미니 보스·일일 퀘스트 (2026-10-01)**: 사용자가 "탕탕특공대처럼 성장 요소와 한 판 안의 컨텐츠가 부족하고, 뽑기까지 너무 많이 해야 한다"는 점을 짚어서 만들었다. ① **마일스톤**(`MatchMilestones`): 3분·6분·처음 클리어에 코어 100/150/300을 계정 전체 1회씩 지급, 받은 기록은 `save.json`의 `milestoneClaimedMask`에 비트로 저장한다 (비트 = 0과 1로 "받음/안 받음"을 번호별로 적어두는 방식). ② **미니 보스**: 3분·6분에 `EnemySpawner`가 보스 프리팹을 줄여서 한 마리씩 소환하고, 처치하면 `GameEvents.OnMiniBossKilled` 신호를 받은 `LevelUpUI`가 3택1 화면을 한 번 띄운다. 이미 선택 화면이 떠 있으면 하나 쌓아뒀다가 이어서 보여준다. ③ **알림 문구** `HUDNotice`: 화면 위쪽에 잠깐 떴다 사라지는 안내 글자로, 미니 보스 출현과 마일스톤 달성을 알려준다. ④ **일일 퀘스트**(`DailyQuests`, `DailyQuestPopup`): 3분 버티기/6분 버티기/클리어하기를 달성하면 로비 창에서 코어 50/100/150을 받는다. 날짜가 바뀌면 달성·수령 기록(`dailyQuestDate` 등)이 초기화된다. `Verify Currency` 검증 도구에 마일스톤·일일 퀘스트(받기 전/후, 재청구, 날짜 변경) 항목을 추가해 모두 통과했다. 전용 미니 보스 모델과 10분 보스의 제대로 된 연출은 아직 없다.
  - 아직 없는 것: 카드·격납고의 드론 그림/3D 프리뷰(지금은 이름과 등급만 표시), 조립 뽑기(잠금 리롤)
- **난이도 시스템 제거 (2026-09-25)**: 쉬움/보통/어려움 3단계를 없애고 다시 하나의 난이도로 되돌림. 메인 메뉴의 난이도 선택 팝업, `GameDifficulty`(배율 계산 스크립트)를 제거하고, 적 체력·접촉 피해량은 항상 원래 밸런스 수치(옛 "어려움" 기준) 그대로 적용되도록 되돌렸다

### 프로젝트 정리와 가벼운 최적화 (2026-10-02)

"최적화"는 게임이 같은 일을 하면서도 컴퓨터 자원(메모리·시간)을 덜 쓰게 고치는 일이다. 웹 브라우저에서 돌리는 게임이라 특히 중요하다. 이번에 한 것은 위험이 낮은 것들이다.

- **`.gitattributes` 추가**: 줄바꿈(글자 파일에서 "다음 줄로 넘어가는" 보이지 않는 표시)이 윈도우와 다른 컴퓨터에서 다르게 저장돼 "LF will be replaced by CRLF" 경고가 계속 뜨던 문제를 막는다. 이제 모든 글자 파일을 LF 한 가지로 통일한다.
- **`.gitignore`에 `*.slnx` 추가**: 유니티가 자동으로 다시 만들어 주는 파일(`Survival_Drone.slnx`)이 저장소에 올라가 있어서 올리지 않게 했다.
- **효과음 17개를 모노로 변경**: 효과음은 좌우 소리를 나눌 필요가 없어서 한쪽 소리(모노)로 바꾸면 웹으로 내려받는 용량이 줄어든다. (배경음악은 그대로 스테레오)
- **HUD 시간 표시**: 화면 위 시간을 매 프레임 새 글자로 만들던 것을, 초가 바뀔 때만 만들게 했다. (글자를 새로 만들 때마다 쓰고 버리는 메모리가 쌓여서 게임이 가끔 멈칫하는 원인이 된다)
- **경험치 구슬(`XPOrb`)**: 구슬이 생길 때마다 씬 전체에서 플레이어를 찾던 것을, 적이 죽을 때 플레이어를 직접 넘겨주게 했다.
- **피격 번쩍임(`DamageFlash`)**: 한 번 맞을 때마다 새로 만들던 타이머를, 번쩍이는 중이면 끝나는 시각만 늦추게 해서 낭비를 줄였다.
- **웹에서 한글이 안 보이던 문제 (2026-10-02, 시험 빌드에서 발견)**: 에디터에서는 컴퓨터에 깔린 한글 글꼴이 대신 쓰여서 문제가 없었지만, 웹 브라우저 안에서는 그런 글꼴을 못 써서 글자가 하나도 안 나왔다. 쓰던 글꼴(Geist)에 한글이 없었기 때문이다. **같은 날 한 첫 번째 수정은 틀렸고, 10/3에 다시 고쳤다.** (처음에는 `Pretendard Std`를 Geist의 "대체 글꼴"로 연결했는데, ① 그 글꼴 파일에는 한글이 한 글자도 없었고, ② 대체 글꼴 연결은 웹 빌드에서 동작하지도 않았다. 에디터의 `HasCharacter`가 윈도우에 깔린 한글 글꼴까지 포함해서 "있다"고 답했기 때문에 처음에 잘못 확인했다.) 지금은 한글 11,172자가 모두 들어 있는 **Pretendard**(`Assets/Fonts/Pretendard-Regular.otf`, SIL 오픈 폰트 라이선스라 게임에 넣어 배포해도 된다. 라이선스 파일도 같은 폴더에 둔다)를 글자(Text)에 **직접** 지정했다. 5개 씬(MainMenu·Lobby·InGame·Hangar·Gacha)의 글꼴 참조를 모두 바꿨고, 앞으로 `SceneUIKit`으로 새로 만드는 화면도 Pretendard를 쓴다. 영어·숫자도 같은 글꼴로 나오기 때문에 모양이 Geist에서 Pretendard로 바뀌었고, 고정폭이던 Geist Mono 자리도 일반 글꼴이 되었다. Geist 글꼴 파일은 지우지 않고 남겨 뒀다. 웹 빌드를 로컬에서 열어 메인 메뉴·로비·인게임 HUD의 한글이 나오는 것을 확인했다. (이 방식은 한글 전체가 한 글꼴에 들어 있어서 아주 드문 글자도 걱정할 필요가 없다. 글꼴 파일이 약 1.6MB 늘어난다)
- **판 도중에 나간 기록 추가 (2026-10-04)**: 테스트 로그에는 사망·클리어로 끝난 판만 남아서, 일시정지(P) 메뉴에서 **"재시작"이나 "메인메뉴"로 중간에 나간 판**은 기록이 없었다. 그러면 CBT에서 "죽은 판"만 보여서, 테스터가 어느 시점에서 지루하거나 어려워서 나갔는지 알 수 없다. 그래서 나갈 때 `match_abandon`이라는 한 줄(스테이지, 나간 방법, 생존 시간, 도달 레벨, 드론 수, 내 전투력)을 남기고, 요약에 "판 도중에 나감 N번 (평균 M:SS 시점)"을 보여 준다. 이 기록은 판 수·클리어율·평균 생존 시간 같은 **"끝난 판" 통계에는 넣지 않는다**(섞으면 클리어율이 틀어진다). 브라우저 탭을 그냥 닫거나 새로고침하며 나가는 경우는 기록하지 못한다(그때는 마지막 `screen` 줄로 짐작한다). 검증 도구 `Verify PlayLog`에 검사 5개를 추가했고, 로컬 WebGL 빌드에서 직접 눌러 확인했다.
- **아직 안 한 큰 작업**: 3D 모델·텍스처 원본 용량 줄이기(저장소가 약 616MB), 적·구슬 재사용(풀링), WebGL 빌드 설정 점검. WebGL 시험 빌드로 실제 크기와 한글 표시를 확인한 뒤 정한다.

### 안정성(에러 방지) 개선

전체 코드를 한 번 훑어보며 "지금 당장은 문제없지만 나중에 실수하면 게임이 멈출 수 있는 부분"을 찾아 안전장치를 추가했다. 예를 들어 메인메뉴·일시정지·설정·레벨업 화면은 모두 버튼 같은 화면 요소를 이름으로 찾아서 연결하는 방식인데, 나중에 그 이름을 실수로 바꾸거나 지우면 찾기에 실패해서 화면 전체가 멈춰버리는 위험이 있었다. 이제는 못 찾아도 경고 로그만 남기고 나머지 기능은 계속 동작하도록 고쳐뒀다.
