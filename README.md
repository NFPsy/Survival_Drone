# Survival : D — Drone Commander (옛 가제: 드론 지휘관)

드론을 지휘하는 사이버펑크 서바이벌 액션 게임 · 신입 게임기획 포트폴리오

> 이 문서는 Unity나 게임 개발을 잘 모르는 사람도 이해할 수 있도록, 어려운 용어가 나올 때마다 짧게 풀어서 설명합니다.

## 게임 소개

| 항목 | 내용 |
|---|---|
| 장르 | 생존 액션 (이동과 성장 중심의 서바이벌 액션) |
| 배경 | 사이버펑크·SF, 로봇이 도시를 장악한 근미래 |
| 그래픽 | 3D (쿼터뷰 시점 — 캐릭터를 비스듬히 위에서 내려다보는 각도. 예: 디아블로 같은 게임의 시점) |
| 플랫폼 | PC (itch.io 배포 예정 — itch.io는 인디 게임을 무료/저가로 올려 배포하는 사이트) |
| 개발 기간 | 1~2개월, 1인 개발 |
| 개발 환경 | Unity(게임을 만드는 프로그램) + Claude(AI 코딩 도우미), 3D 모델은 VARCO 3D 제작·에셋스토어 구매 병행, Blender(3D 모델 편집 프로그램)로 다듬음 |
| 형상 관리 | GitHub (코드 변경 이력을 저장하고 되돌릴 수 있게 관리하는 서비스) |

주인공은 로봇이 도시를 장악한 근미래 세계의 엔지니어다. 직접 싸우는 대신, 자신을 따라다니는 여러 대의 드론을 통해 싸운다. **플레이어는 이동만 담당**하고, 공격은 드론들이 자동으로 처리한다.

핵심 재미는 시간이 지나며 얻는 드론들을 **어떤 조합으로 키워나가는가**에 있다. 같은 시작이라도 어떤 드론을 먼저 얻고 어떻게 강화하는지에 따라 매판 다른 전략이 만들어지도록 설계했다.

## 조작법

| 입력 | 동작 |
|---|---|
| WASD / 게임패드 왼쪽 스틱 | 이동 (방향키는 이동에 쓰지 않는다) |
| **마우스** | **폭발 드론의 폭발 위치 정하기** (폭발 드론이 있고 판이 진행 중일 때만. 마우스를 움직이면 게임 안의 조준 커서가 움직이고, 그 커서가 가리키는 바닥이 폭발 지점이다. 플레이어에서 최대 7m. 이때 실제 마우스 커서는 숨겨지고 바닥의 폭발 범위 원이 커서 역할을 한다. 일시정지·레벨업 선택·결과 화면에서는 커서가 다시 나타난다. 속도는 설정의 **마우스 감도**로 조절한다) |
| **스페이스바** | **오버드라이브 발동** (게이지가 가득 찼을 때만) |
| **P** | 일시정지 메뉴 열기/닫기 (계속하기/재시작/로비/메인메뉴, 아래쪽에서 배경음악·효과음 볼륨도 따로 조절 — 슬라이더 또는 숫자(%) 입력, 메인 메뉴의 설정과 같은 값을 공유) |
| (없음) | 평소 공격은 드론이 자동으로 수행 |

## 기본 진행 방식

- 한 판은 **9분(540초)까지 일반 로봇과 싸우고, 9분이 되면 보스전**으로 넘어간다. 보스전이 시작되면 남아 있던 일반 로봇(미니 보스 포함)은 **전부 그 자리에서 터져 사라지고**(경험치 구슬은 남는다), 플레이어 주변에 **붉은 원형 경기장**(반지름 22m)이 생기며 **보스 한 마리**만 나온다. 플레이어와 보스는 이 원 밖으로 나갈 수 없다. **보스를 쓰러뜨리면 승리**한다. 화면 위쪽 시간 표시는 보스전 동안 "보스전"으로 바뀌고, 그 아래에 BOSS 체력바가 나온다. 자세한 규칙은 아래 "보스전" 항목을 본다. (옛 방식은 10분이 지나면 "남은 로봇을 모두 처치"해야 이겼다. InGame 씬의 `EnemySpawner`에서 `Use Boss Fight`를 끄면 옛 방식으로 돌아간다.)
- 시간이 지날수록 로봇이 더 많이, 더 강하게 등장한다 (아래 "적 시스템" 표 참고).
- **미니 보스**: 한 판 도중 **3분**과 **6분**에 중간 보스가 한 마리씩 나온다. 나올 때 화면 위쪽에 "미니 보스 출현!" 알림이 뜨고, **처치하면 레벨업 때와 같은 3택1 선택지(드론 추가·강화 등)를 한 번 더 받는다.** (아직 전용 모델이 없어서 보스 모델을 작게 줄여 주황색으로 칠한 임시 모습이다.)
- **마일스톤**(중간 목표 보상): 판 도중 정해진 시간에 도달하면 코어(뽑기에 쓰는 재화)를 준다. **3분 도달 +100 / 6분 도달 +150 / 처음 클리어 +200**이고, 각각 **스테이지마다 따로 딱 한 번씩** 받는다. (스테이지 1에서 받았어도 다른 스테이지에서 다시 달성하면 또 받을 수 있고, 같은 스테이지에서는 이미 받은 뒤에 다시 해도 안 나온다. 스테이지는 모두 5개이고, 오를수록 보상이 늘어난다: 스테이지 1은 3분 +100 / 6분 +150 / 처음 클리어 +200, 스테이지 2는 +150 / +225 / +300, 스테이지 3은 +200 / +300 / +400, 스테이지 4는 +250 / +375 / +500, 스테이지 5는 +300 / +450 / +600. 규칙은 "3분 = 50 × (스테이지 번호 + 1), 6분 = 3분의 1.5배, 클리어 = 3분의 2배"이고, 다섯 스테이지를 다 받으면 합계 4,500코어다.) 판에서 목표를 달성하면 화면 위쪽에 "스테이지 1 마일스톤 3분 달성! 로비에서 코어 +100을 받을 수 있어요"처럼 알림이 뜨고, 코어는 **로비의 "마일스톤" 창**(오른쪽 아래 버튼)에서 스테이지를 고른 뒤 3분 / 6분 / 클리어 칸을 골라 **"획득"을 눌러야** 들어온다. (일일 퀘스트와 같은 방식이라, 자동으로 들어오지 않는다.)
- **일일 퀘스트**: 로비 오른쪽 아래 "일일 퀘스트" 버튼으로 연다. **출석하기 +150 / 3분 버티기 +50 / 6분 버티기 +75 / 클리어하기 +125** 코어이다(하루에 모두 받으면 400, 창에서는 출석하기가 맨 위에 보인다). 앞의 셋은 한 판에서 조건을 채우면, **출석하기는 그날 처음 로비에 들어오면** 자동으로 "달성" 표시가 되며, 창에서 **"받기" 버튼을 눌러야** 코어가 들어온다. 하루(기기 날짜 기준)가 지나면 모두 같은 시각에 초기화돼서 매일 다시 할 수 있다.
- **XP**(경험치, Experience Point의 줄임말)를 모으면 **레벨업**한다. 로봇을 처치하면 그 자리에 XP 구슬이 떨어지고, 플레이어가 가까이 가면 자동으로 흡수된다. 레벨업할 때마다 3개 선택지 중 하나를 골라 드론을 늘리거나 강화하거나, 능력치를 올린다.
- 화면 위에는 항상 **HUD**(Head-Up Display — 체력/시간처럼 지금 상태를 알려주는 화면 표시)가 떠 있어서, 체력바·XP바·오버드라이브 게이지·레벨·남은 시간을 바로 확인할 수 있다.

## 오버드라이브 — 이 게임의 유일한 액티브 스킬

플레이어가 직접 누르는 버튼은 이것 하나뿐이다.

- 로봇을 처치할 때마다 **오버드라이브 게이지**가 찬다 (엘리트 로봇은 한 마리로 일반 로봇 약 6마리분을 채워준다).
- 게이지가 가득 차면 **스페이스바**로 발동 — 5초 동안 모든 공격 드론의 공격 속도가 **2.5배**가 되고, 이동 속도도 25% 빨라진다.
- **단, 그 5초 동안은 내가 받는 피해도 2배가 된다.**

**왜 이렇게 설계했나 (기획 의도)**

원래 이 게임은 "플레이어는 이동만, 공격은 드론이 자동"이라는 구조였다. 그런데 실제로 만들어놓고 보니 한 판 10분 동안 플레이어가 내리는 판단이 *이동 방향*과 *레벨업 3택1*밖에 없어서, 그 사이의 순간순간이 밋밋했다.

그래서 "지금 쓸까, 참을까"라는 판단을 하나 심었다. 핵심은 **피해 2배라는 대가**다:

- 게이지는 처치로만 차기 때문에, **적이 많이 몰린 순간 = 게이지가 빨리 차고 발동 이득도 큰 순간**이다.
- 그런데 적이 많이 몰린 순간은 동시에 **가장 위험한 순간**이기도 하다.
- 결국 "이득이 가장 클 때가 가장 위험할 때"가 되어, 발동 타이밍 자체가 매번 다른 선택이 된다.

회복 드론만은 이 배율에서 일부러 제외했다. 회복까지 빨라지면 "위험을 감수한다"는 전제가 무너지기 때문이다.

화면에서는 발동 중 가장자리가 주황색으로 맥동한다. (빨강=죽기 직전 경고, 주황=내가 선택한 위험, 시안=안전/성장 — 색으로 상황을 구분할 수 있게 나눠뒀다)

### 엘리트 로봇

일반 로봇 중 일부가 **엘리트**로 등장한다 (30초 이후, 8% 확률).

| 항목 | 일반 대비 |
|---|---|
| 체력 | 3배 |
| 크기 | 1.35배 (한눈에 구분됨) |
| 색 | 시안색으로 물듦 |
| 주는 XP | 3배 |
| 오버드라이브 게이지 | 약 6배 |
| 부딪힐 때 피해 | **동일** (일부러 안 올림) |

부딪힐 때 피해를 안 올린 이유: 엘리트를 "더 아픈 적"이 아니라 "잡는 데 오래 걸리지만 보상이 큰 적"으로 만들어야, 플레이어가 피하지 않고 **노리게** 되기 때문이다. 덕분에 "저놈부터 잡을까?"라는 우선순위 판단이 생긴다.

오버드라이브와도 맞물린다 — 엘리트를 잡으면 오버드라이브가 빨리 차고, 오버드라이브 중에는 엘리트를 잡기 쉬워진다.

## 드론 시스템

드론은 최대 5~6개까지 동시에 보유할 수 있으며, 게임 시작 시 근접 드론 하나만 가지고 출발한다. 드론 하나는 5단계까지 강화할 수 있고, 5단계에 도달하면 상위 형태로 변신한다.

| 드론 | 역할 | 강화 시 좋아지는 것 |
|---|---|---|
| 근접 드론 | 주인공 주위를 돌며 가까운 적 공격 | 도는 속도 또는 크기 |
| 저격 드론 | 가장 가까이 있는 적을 원거리 공격 | 공격력 또는 공격 속도 |
| 폭발 드론 | 일정 시간마다 주변 전체에 범위 피해 | 폭발 범위 또는 피해량 |
| 회복 드론 | 주인공 체력을 서서히 회복 | 회복량 또는 회복 주기 |
| 수집 드론 | 아이템·경험치를 자동으로 끌어모음 | 끌어당기는 범위 |

## 적 시스템 — 폭주한 보안 로봇

| 로봇 종류 | 체력 | 이동 속도 | 부딪힐 때 피해 | 처음 등장 시점 |
|---|---|---|---|---|
| 약한 로봇 | 14 | 보통 | 6 | 시작부터 |
| 튼튼한 로봇 | 38 | 느림 | 10 | 1분 30초부터 |
| 빠른 로봇 | 8 | 빠름 | 6 | 2분 30초부터 |
| 강한 로봇 | 95 | 느림 | 18 | 6분째부터 |
| 보스 로봇 | 500 (보스전에서는 ×4) | 느림 (분노 ×1.3) | 25 (돌진·내려찍기는 위 보스전 패턴 피해) | 9분째, 한 번만 (보스전) |

로봇이 나오는 10분을 세 구간(처음 1분 30초 / 중간 4분 30초 / 마지막 4분)으로 나누어, 로봇 등장 속도와 최대 동시 등장 수가 달라진다. (이렇게 시간에 따라 점점 어려워지게 짜놓은 것을 "난이도 곡선"이라고 부른다.)

**미니 보스**는 위 표의 5종과 별개로 3분·6분에 한 번씩 나온다. 보스 로봇의 모습을 60% 크기로 줄인 임시 모델을 쓰고, 체력은 보스(500)의 **50%(3분) / 80%(6분)**다. (이 배율은 `EnemySpawner.cs`의 `miniBossHealthMultipliers`에서 바꾼다.) 전용 모델이 없어서 일반 적과 구분되도록 발밑에 **주황 링 효과**를 붙였다(2026-10-10). 540초에 나오는 최종 보스는 더 크고 붉은 링과 불씨가 붙는다.

**건물(기둥)과 적 (2026-10-05)**: 경기장에는 건물 5개가 서 있다. 원래는 **플레이어만 건물에 막히고 적은 통과**했는데, 적의 이동 코드가 물리 충돌을 보지 않고 위치를 직접 옮기는 방식이라서 그랬다. 지금은 적도 건물을 통과하지 못한다. 적이 플레이어에게 걸어가다가 건물이 사이를 가로막고 있으면 플레이어 대신 **건물의 모서리를 향해 걷고**(두 모서리 중 돌아가는 길이 더 짧은 쪽), 모서리를 지나면 다시 플레이어를 향해 곧장 걷는다. 건물 안에서 태어난 적은 가장 가까운 면 바깥으로 밀려 나온다. 물리 엔진을 쓰지 않고 계산만 해서 웹(WebGL)에서도 가볍다. 건물에 `EnemyObstacle` 스크립트가 붙어 있고, 크기와 위치는 건물의 `BoxCollider`에서 읽으므로 건물을 옮기거나 새로 만들 때 코드를 고칠 필요가 없다(새 건물에는 이 스크립트만 붙이면 된다). 이제 플레이어가 건물 뒤로 돌아서 적을 모는 플레이가 가능하다.

## 프로젝트 구조

Unity 프로젝트는 보통 이런 폴더들로 이루어진다. 각각이 뭘 하는 폴더인지 처음 보면 낯설 수 있어서 간단히 설명을 붙였다.

```
Assets/                    (게임에 쓰이는 모든 것이 들어있는 폴더)
├── Scripts/               (게임 동작을 정의하는 C# 코드 파일들)
│   ├── Core/                게임 공용 시스템 (체력, 이벤트, 매치 타이머)
│   ├── Player/               플레이어 이동, 능력치, 경험치, 오버드라이브(액티브 스킬)
│   ├── CameraControl/         쿼터뷰 카메라 추적
│   ├── Enemies/              적 데이터/AI(적 스스로 움직이고 공격하는 로직)/스폰(적을 생성하는 것)
```

  - **뽑기 로직** `GachaSystem`: 등급 확률(N 55% / R 30% / SR 12.5% / SSR 2.5%), 1회 300코어 / 10연 2,700코어, **천장 70회**(70번째 뽑기에서 SSR 확정, 화면 밖 검증에서 500만 번 뽑았을 때 SSR 1개당 평균 33.19회로 기획 수치 33.2와 일치). 여기에 **소천장**이 더해져 천장이 2단이다: SR 이상이 한 번도 안 나온 채 **10번째 뽑기**가 되면 그 뽑기는 SR 이상이 확정된다(SR 이상이 나오면 다시 처음부터 센다. 확정으로 나오는 뽑기도 SSR은 기본 확률 2.5%로 따로 굴려서 맞으면 SSR, 아니면 SR이다). 그래서 "10회 안에 SR 이상이 하나는 나온다". SSR을 얻는 데 드는 평균 비용(약 33.3회)은 그대로이고, SR 이상 비율만 15.4%에서 약 19%로 오른다
  - **재화와 저장**: 코어(유료 재화)·크레딧(플레이로 버는 재화)을 관리하고 `save.json` 파일에 저장해서 다음 실행에도 유지. 처음 시작하면 코어 2,700을 준다
  - **로비 화면과 스테이지 선택**: 메인 메뉴 → 로비 → 출격 흐름. 스테이지는 3개이고 앞 스테이지를 클리어해야 다음이 열리며, 최고 생존 시간을 기록한다. 스테이지가 올라갈수록 적의 체력·접촉 피해에 배율이 곱해진다(아래 밸런스 표 참고)
  - **보유 드론 관리** `DroneInventory`: 뽑은 드론을 내 목록에 반영한다. 드론은 종류당 1개만 가지고, 이미 가진 드론이 또 나오면 → 더 높은 등급이면 **승급**(강화 레벨은 유지), 같거나 낮은 등급이면 **조각**(강화 재료)으로 바뀐다. 조각과 크레딧으로 드론을 최대 레벨 5까지 강화할 수 있고, 출격용 슬롯 2개에 드론을 장착한다. 처음 시작하면 근접 N + 저격 N 드론을 준다
  - **전투력**: 장착한 드론의 등급·레벨을 합친 수치(시작 상태 100). 로비의 스테이지 카드에 권장 전투력과 나란히 보이며, 권장 이상이면 초록 / 70~100%면 주황 / 70% 미만이면 빨강으로 표시된다
  - **뽑기 전체 흐름** `GachaController`: 화면이 "1회 뽑기"나 "10연 뽑기"를 요청하면 ① 코어를 먼저 내고 ② 뽑고 ③ 결과를 내 드론 목록에 반영하고 ④ 천장 횟수를 저장하는 순서를 한 곳에서 처리한다. 코어가 모자라면 아무것도 차감하지 않고 "부족" 알림만 보낸다. 천장 횟수도 저장해서 게임을 껐다 켜도 이어진다. 뽑을 때마다 콘솔에 "몇 회 뽑기 완료: 등급별 개수 · 신규 · 승급 · 조각 · 코어 잔액 · 천장" 한 줄이 남아서 나중에 테스트 기록으로 쓸 수 있다
  - **뽑기 화면** `Gacha` 씬: 로비의 "뽑기" 버튼으로 들어간다. 배너, 등급별 확률 요약, **천장 게이지**("SSR 확정까지 누적 n / 70" + 채워지는 막대)와 그 아래 **소천장 게이지**("SR 이상 보장까지 누적 n / 10"), 1회(300코어)·10연(2,700코어, 10% 할인 뱃지) 버튼, 코어 잔액이 있다. 코어가 모자라면 가격 글자만 빨갛게 바뀌고, 눌러 보면 "코어가 부족합니다" 팝업이 뜬다. "확률 보기"를 누르면 확률 공개 팝업이 열려 등급별 확률과 천장·초기화·10연 규칙을 문장으로 보여준다. **화면에 적힌 확률·가격·천장 횟수는 전부 뽑기 로직이 쓰는 데이터 파일(`GachaTable`)에서 그대로 읽어온다** — 표기용 숫자를 따로 적지 않으므로 표기와 실제가 어긋날 수 없다
  - **뽑기 결과 화면**: 뽑기를 하면 카드 뒷면("?")이 먼저 깔리고, 카드를 한 장씩 순서대로 뒤집으며 공개한다. 공개 시간은 등급이 높을수록 길어서(N 0.4초 / R 0.6초 / SR 1.0초 / SSR 2.0초) 기다리는 동안 카드 테두리가 그 등급 색으로 반짝이고, SSR이 나오는 순간 화면이 금색으로 번쩍인다. 카드마다 **NEW**(처음 얻은 드론) / **승급 N → R**(같은 드론이 더 높은 등급으로 나옴) / **중복 조각 +10**(같거나 낮은 등급이라 조각이 됨)이 표시된다. 우상단 **스킵**을 누르면 언제든 남은 카드를 한 번에 공개하고(반복 뽑기가 지루하지 않게), 다 공개되면 **확인**(닫기)과 **다시 뽑기**(같은 방식으로 한 번 더, 코어가 모자라면 눌리지 않음) 버튼이 나온다
  - **격납고 화면** `Hangar` 씬: 로비의 "격납고" 버튼으로 들어간다. 왼쪽에 드론 5종 목록(등급·레벨, 장착 중 표시, 아직 못 얻은 드론은 흐리게 "미획득")이 있고, 하나를 고르면 오른쪽에 상세가 나온다: 전투력, 성능 배율(등급 배율 × 강화 배율로 나눠서 표시), **조각 진행바**(예: 조각 12 / 30), 필요한 크레딧, **강화 버튼**, **조각 교환 버튼**. 조각이나 크레딧이 모자라도 버튼을 눌러 보면 무엇이 부족한지 안내해 준다. **조각 교환**은 크레딧을 내고 고른 드론의 조각을 사는 기능이다(조각 10개 = 크레딧 500, 하루 3번까지, 일일 퀘스트와 같은 시각에 횟수가 새로 시작된다). 조각은 원래 뽑기에서 같은 드론이 또 나올 때만 얻을 수 있어서 강화가 느렸고 크레딧은 남아돌았기 때문에, 남는 크레딧을 조각으로 바꿔 쓸 수 있게 했다. 이미 최대 레벨인 드론은 조각이 필요 없어서 교환할 수 없다. 교환한 기록은 테스트 로그에 남는다. 아래쪽 **출격 슬롯 2개**에서 드론을 골라 장착할 수 있다(이미 다른 슬롯에 있는 드론을 끼우면 서로 자리가 바뀌고, 같은 슬롯을 다시 누르면 해제). 장착이 바뀌면 "내 전투력"이 바로 갱신되고 로비에도 반영된다
  - **판 종료 보상과 결과 화면**: 판이 끝나면(클리어든 실패든) 재화를 지급한다. 판 보상은 **크레딧만** 준다. 클리어하면 스테이지마다 달라서 크레딧 스테이지 1 +300 / 2 +450 / 3 +600 / 4 +750 / 5 +900이고, 코어는 클리어해도 주지 않는다(클리어에 대한 코어 보상은 마일스톤의 "처음 클리어"가 대신한다). 실패해도 **크레딧만** 받는다. 코어는 마일스톤과 일일 퀘스트로만 얻는다. 크레딧에도 조건이 있다: 생존 시간이 **1분 미만이면 보상이 없고**(일부러 금방 죽어서 재화를 모으는 것을 막기 위해), 1분을 넘긴 뒤부터는 버틴 시간에 **비례**해서 받는다(1분 → 0, 로봇이 나오는 10분을 다 버티면 클리어 크레딧과 같아지는 직선). 예: 스테이지 1에서 5분 30초까지 버티고 죽으면 코어 +0 / 크레딧 +150이다. 일찍 져서 보상이 0이면 결과 화면에 "1분 이상 버텨야 보상을 받을 수 있어요"라는 안내가 나온다. 결과 화면(GAME CLEAR / GAME OVER)에는 생존 시간 아래에 **획득 보상** 영역이 생겼고, 코어·크레딧 숫자가 0에서부터 약 0.8초 동안 올라가는 연출로 보여준다. 버튼은 **로비로**(방금 얻은 재화가 반영된 로비로 이동)와 **재도전**(같은 스테이지를 처음부터 다시)이다. 클리어하면 다음 스테이지가 열린다
  - **장착한 드론으로 판 시작**: 이제 격납고에서 장착한 드론 2개를 들고 판을 시작한다(처음 시작하면 근접 N + 저격 N). 그 드론들에는 뽑기 **등급 배율 × 강화 배율**(예: 근접 SR ×1.25, 회복 SSR ×1.45)이 곱해진다. 배율은 판 안 레벨업(레벨당 +16%)과 같은 능력치 전부에 곱해진다 — 근접은 회전 속도·공격 범위, 저격은 피해량·공격 속도, 폭발은 피해량·범위, 회복은 회복 빈도, 수집은 자석 범위. 장착하지 않은 드론이나 레벨업 선택지로 새로 얻는 드론은 ×1.0이다. 이제 "플레이 → 뽑기 → 장착 → 다시 플레이" 한 바퀴가 실제로 돈다
  - **웹(WebGL) 빌드 대비 저장 동기화 (2026-09-30)**: 웹 게임은 진짜 하드디스크가 없어서 `save.json`이 먼저 메모리 안의 가짜 파일로 써지고, 그 내용이 브라우저 저장소로 옮겨져야 새로고침 후에도 남는다. 이 "옮기기"는 자동이 아니라서, 저장할 때마다 유니티 웹 플레이어의 `JS_FileSystem_Sync` 함수를 부르도록 `WebGLFileSync`를 추가했다(PC·에디터에서는 아무 일도 하지 않음). 볼륨 설정도 설정 패널을 닫을 때 `PlayerPrefs.Save()`로 한 번 저장한다. 실제 웹 빌드에서 새로고침 후 저장이 남는지는 빌드로 확인해야 한다. 웹 빌드 압축 설정도 itch.io에서 안전한 **Gzip + 압축 해제 대체(Decompression Fallback) 켜기**로 바꿨다(기존 Brotli, 대체 꺼짐 — itch.io는 서버 설정을 직접 바꿀 수 없어서 브라우저에 따라 게임이 안 뜰 수 있음)
  - **테스트(CBT) 기록 수집 (2026-09-30)**: 웹 게임은 테스터의 브라우저 안에만 파일이 생겨서 개발자가 기록을 받을 수 없다. 그래서 게임이 스스로 플레이 기록을 쌓고, 테스터가 로비의 **"테스트 로그"** 창에서 **복사**하거나 **파일로 저장**해서 보내게 했다. 기록에는 게임을 켠 시각, 화면 이동(뽑기·격납고 같은 화면만. 10/18부터 메인 메뉴·로비·InGame 이동은 남기지 않는다), 뽑기 결과와 코어 수지, 판 결과(스테이지·클리어 여부·생존 시간·도달 레벨·받은 보상), 강화·장착, 스테이지 해금이 들어가고, 맨 위에는 **요약**(판 수, 클리어율, 판당 평균 보상, 뽑기 횟수, SSR 개수, 첫 뽑기 전에 몇 판 했는지 등)이 자동으로 붙는다. 요약에는 **실패한 판 평균 생존 시간**(게임 시간 기준)과 **판당 평균 실제 소요 시간**(일시정지·레벨업 선택 화면 포함, 클리어한 판만 따로도 표시)도 들어가서 한 판이 실제로 몇 분인지 판단하는 근거가 된다. 이 요약과 기록이 시뮬레이터 가정값(클리어율 40/50/60%, 판당 코어 등)을 실제 플레이로 보정하는 근거가 된다. 개인정보는 남기지 않고, 테스터는 임의의 6자리 번호로만 구분한다. 복사 버튼이 브라우저에서 막히면 파일 저장을 쓰면 된다. **정식 출시 전에는 이 버튼을 숨길 예정**이다
  - **마일스톤·미니 보스·일일 퀘스트 (2026-10-01)**: 사용자가 "탕탕특공대처럼 성장 요소와 한 판 안의 컨텐츠가 부족하고, 뽑기까지 너무 많이 해야 한다"는 점을 짚어서 만들었다. ① **마일스톤**(`MatchMilestones`): 3분·6분·처음 클리어에 코어 100/150/300을 계정 전체 1회씩 지급, 받은 기록은 `save.json`의 `milestoneClaimedMask`에 비트로 저장한다 (비트 = 0과 1로 "받음/안 받음"을 번호별로 적어두는 방식). ② **미니 보스**: 3분·6분에 `EnemySpawner`가 보스 프리팹을 줄여서 한 마리씩 소환하고, 처치하면 `GameEvents.OnMiniBossKilled` 신호를 받은 `LevelUpUI`가 3택1 화면을 한 번 띄운다. 이미 선택 화면이 떠 있으면 하나 쌓아뒀다가 이어서 보여준다. ③ **알림 문구** `HUDNotice`: 화면 위쪽에 잠깐 떴다 사라지는 안내 글자로, 미니 보스 출현과 마일스톤 달성을 알려준다. ④ **일일 퀘스트**(`DailyQuests`, `DailyQuestPopup`): 3분 버티기/6분 버티기/클리어하기를 달성하면 로비 창에서 코어 50/100/150을 받는다. 날짜가 바뀌면 달성·수령 기록(`dailyQuestDate` 등)이 초기화된다. `Verify Currency` 검증 도구에 마일스톤·일일 퀘스트(받기 전/후, 재청구, 날짜 변경) 항목을 추가해 모두 통과했다. 전용 미니 보스 모델과 10분 보스의 제대로 된 연출은 아직 없다.
  - 아직 없는 것: 카드·격납고의 드론 그림/3D 프리뷰(지금은 이름과 등급만 표시), 조립 뽑기(잠금 리롤)
- **난이도 시스템 제거 (2026-09-25)**: 쉬움/보통/어려움 3단계를 없애고 다시 하나의 난이도로 되돌림. 메인 메뉴의 난이도 선택 팝업, `GameDifficulty`(배율 계산 스크립트)를 제거하고, 적 체력·접촉 피해량은 항상 원래 밸런스 수치(옛 "어려움" 기준) 그대로 적용되도록 되돌렸다

### 프로젝트 정리와 가벼운 최적화 (2026-10-02)

"최적화"는 게임이 같은 일을 하면서도 컴퓨터 자원(메모리·시간)을 덜 쓰게 고치는 일이다. 웹 브라우저에서 돌리는 게임이라 특히 중요하다. 이번에 한 것은 위험이 낮은 것들이다.

- **`.gitattributes` 추가**: 줄바꿈(글자 파일에서 "다음 줄로 넘어가는" 보이지 않는 표시)이 윈도우와 다른 컴퓨터에서 다르게 저장돼 "LF will be replaced by CRLF" 경고가 계속 뜨던 문제를 막는다. 이제 모든 글자 파일을 LF 한 가지로 통일한다.
- **`.gitignore`에 `*.slnx` 추가**: 유니티가 자동으로 다시 만들어 주는 파일(`Survival_Drone.slnx`)이 저장소에 올라가 있어서 올리지 않게 했다.
- **효과음 17개를 모노로 변경**: 효과음은 좌우 소리를 나눌 필요가 없어서 한쪽 소리(모노)로 바꾸면 웹으로 내려받는 용량이 줄어든다. (배경음악은 그대로 스테레오)
- **HUD 시간 표시**: 화면 위 시간을 매 프레임 새 글자로 만들던 것을, 초가 바뀔 때만 만들게 했다. (글자를 새로 만들 때마다 쓰고 버리는 메모리가 쌓여서 게임이 가끔 멈칫하는 원인이 된다)
- **경험치 구슬(`XPOrb`)**: 구슬이 생길 때마다 씬 전체에서 플레이어를 찾던 것을, 적이 죽을 때 플레이어를 직접 넘겨주게 했다.

- **보스 돌진·내려찍기 애니메이션 추가 (2026-10-18)**: 보스가 돌진할 때는 **달리는 동작**, 내려찍을 때는 **팔을 들어 올렸다가 내려치는 동작**을 한다. (그전에는 어떤 패턴이든 걷기·서 있기 동작만 나왔다.) 두 동작은 VARCO 3D로 만든 FBX를 Blender로 손봐서 `Assets/Models/Enemies/Boss/Boss_Run.fbx`·`Boss_Slam.fbx`로 넣었다.
  - **달리기**: 원본은 몸이 오른쪽(+X)을 보고 있어서 몸 전체를 80도 돌려 앞을 보게 했다(주인공 달리기와 같은 문제·같은 해결). 돌진이 시작되면 달리기 동작, 끝나면 다시 서 있기/걷기로 돌아온다.
  - **내려찍기**: 원본은 228프레임짜리 긴 동작이라 "준비 → 내려치기"까지인 60~135프레임만 잘라 썼다(뒤쪽은 바닥에 엎드린 채 굳은 자세라 필요 없다). 몸이 12도 돌아 있어서 반대로 돌려 맞췄다. **동작이 끝나는 순간이 바닥을 치는 순간**이라서, 재생 속도를 `2.5초 ÷ 예고 시간`(보통 약 1.56배, 분노 약 1.92배)으로 맞춰 예고 원이 다 차오르는 순간 내려치게 했다. 분노 때 연속 2번 내려찍을 때도 매번 처음부터 다시 한다.
  - **연결 방식(쉬운 설명)**: Unity의 Animator(동작들을 상태로 묶어 두고 조건에 따라 바꿔 주는 장치)에 `Run`·`Slam` 상태를 추가했다. 코드(`BossBrain.cs`)는 내려찍기 예고가 시작될 때 `Slam` 신호와 재생 속도를, 돌진이 시작/끝날 때 `Dash` 스위치를 켜고 끌 뿐이다. 모델 쪽 변환 스크립트(`Tools/Blender/export_rotated.py`)에는 "이 프레임 구간만 내보내기" 옵션을 추가했다.
  - **확인한 것**: 플레이 모드에서 보스전을 돌려 걷기 → 내려찍기(예고 시작 시 동작 시작, 예고가 끝나는 순간 내려침, 약 0.4초 뒤 서 있기로 복귀) → 돌진(달리기 동작 중 앞을 보고 달림) 흐름을 확인했고, 발·몸통 방향을 재서 걷기와 같은 앞쪽인지 확인했다. **아직 확인 못 한 것**: 내려찍기 몸통이 어깨 기준 약 20도 비껴 보이는 것이 실제 화면에서 거슬리는지(손으로 플레이해서 봐야 함), 웹(WebGL) 빌드에서의 모습.
- **테스트 로그 보강 2·3단계 (2026-10-18)**: OBT 로그로 "몇 분에 어려워지는지", "초반에 뭘 골랐는지", "회복·폭발 드론이 정말 약한지"를 숫자로 볼 수 있게 판 기록 줄 끝에 항목 3개를 더했다. (아래 예시 속 숫자는 모양을 보이려고 지어낸 값이다)
  - **분별 받은 피해** `분별피해=1분12/4분80/10분210`: 받은 피해를 1분(0~60초)씩 끊어서 합쳤다. 피해를 안 받은 분은 적지 않고, 보스전(540초 이후)과 10분이 넘은 때는 마지막 "10분" 칸에 센다. 일시정지·선택 화면 시간은 빼고 센 게임 시간 기준이다. 기존 `받은피해=`(적 종류별) 바로 뒤에 붙는다.
  - **레벨업 선택 순서** `선택순서=M,M,N:Sniper,U:Sniper,H`: 고른 순서대로 이동속도 `M`, 체력 `H`, 새 드론 `N:드론이름`, 드론 강화 `U:드론이름`을 적는다. 기존 `레벨업선택=`(횟수)은 순서를 알 수 없어서 순서를 따로 남겼다. 판 도중에 나갔을 때(이탈) 기록에도 붙는다.
  - **드론별 기여** `드론기여=Sniper피해2400/Melee피해300/Heal회복120`: 드론 종류마다 적에게 **실제로 깎은 체력**(공격 드론)과 플레이어 체력을 **실제로 채운 양**(회복 드론)을 합쳤다. 남은 체력보다 센 마지막 일격은 남은 체력만큼만 세고, 체력이 가득일 때의 회복은 0으로 세서 수치가 부풀려지지 않는다. 수집 드론은 피해도 회복도 없어서 세지 않는다. 기존 `최종드론=` 바로 뒤에 붙는다(이탈 기록에도 붙음). 이를 위해 `EnemyAI.ApplyDamage`가 "실제로 깎인 체력"을 돌려주도록 바꿨고(반환값을 쓰지 않는 기존 호출은 그대로 동작), 새 도우미 `DroneContributionLog.cs`가 값을 모은다.
  - **분석기**(`Tools/LogAnalyzer/analyze_logs.py`): 새 항목을 읽어서 보고서에 "구간별 받은 피해"(분마다 판당 받은 피해와 그 구간에서 죽은 판 수), "드론별 기여"(드론마다 가진 판 수·평균 레벨·판당/초당 기여), "레벨업 선택 순서"(처음 3번 안에 이동속도를 고른 비율, 처음 4번의 흔한 조합) 표를 만든다. 옛 형식 기록에는 이 항목이 없어서 표가 나오지 않는다(옛 기록이 섞여도 새 기록만 센다).
  - **검증**: 로그 검증 메뉴(`Verify PlayLog`)에 새 항목 검사를 넣어 전부 통과했고(선택 순서 문장, 분별 칸 1·2·10분, 빈 칸 생략, 드론 기여 요약과 Reset), 플레이 모드에서 실제 판을 돌려 근접·저격·폭발 드론 기여와 회복 기록이 쌓이는 것을 확인했다. 분석기는 가짜 새 형식 로그로 시험했다. **웹에서 실제로 찍히는 모양과 회복 드론의 실제 판 기록은 OBT 로그로 확인이 남았다.**
- **판 안 배경음악을 두 곡으로 늘림 (2026-10-18)**: 한 판이 약 10분인데 곡이 하나뿐이라 지루할 것 같아서, AI로 만든 새 곡 `Survival Protocol`(약 4분)을 `Assets/Resources/Music/BGM_SurvivalProtocol.mp3`로 추가했다. **판 안(InGame)에서만** 새 곡 → 원래 곡(`BGM_Main`) → 다시 새 곡 순서로 이어서 틀고(판이 시작될 때마다 새 곡부터), 메인 메뉴·로비는 지금처럼 원래 곡만 나온다. (판이 끝나 로비로 돌아오면 순서대로 틀던 것을 끝내고 원래 곡 한 곡 반복으로 되돌아온다. 이때 곡이 한 번 끊기고 처음부터 다시 시작된다.)
  - **어떻게 동작하나(쉬운 설명)**: `AudioManager`에 "여러 곡을 순서대로 틀기"를 만들었다. 곡이 끝난 것을 매 프레임 확인해서 다음 곡을 틀고, 마지막 곡이 끝나면 처음으로 돌아간다. 판이 시작될 때마다 목록의 첫 곡(새 곡)부터 처음부터 튼다. 메인 메뉴나 로비로 돌아가면 다시 한 곡 반복으로 돌아온다(기억해 둔 메인 메뉴 곡으로). 두 번째 곡 파일은 코드(`GameManager`)가 `Resources` 폴더에서 이름으로 찾아서, 씬 파일은 건드리지 않았다. 이 파일이 없으면 예전처럼 원래 곡만 반복한다.
  - **음량 맞추기**: 분석해 보니 새 곡이 원래 곡보다 평균 4.7dB 작았다(-17.2 vs -12.5dB). 유니티의 소리 크기는 1을 넘길 수 없어서 새 곡을 키울 수는 없다. 그래서 **판 안에서만** 원래 곡을 70%로 낮춰 두 곡의 차이를 줄였다. 설정 창의 음악 볼륨은 두 곡에 똑같이 적용된다.
  - **빌드 크기**: 새 곡 파일은 5.9MB(mp3)이고 빌드에서 압축된다(원래 곡과 같은 Vorbis 품질 0.7, 스트리밍 방식). 웹 빌드가 몇 MB 늘어난다.
  - **확인한 것**: 에디터 플레이 모드에서 판 시작 → 새 곡(음량 100%) → 원래 곡(70%) → 다시 새 곡으로 넘어가는 것, 메인 메뉴 곡으로 되돌렸을 때 한 곡 반복·음량 100%로 돌아오는 것을 확인했다(곡 끝 근처로 건너뛰어서 시험). **아직 확인 못 한 것**: 실제로 귀로 들었을 때 곡이 바뀌는 순간이 자연스러운지, 웹에서 곡이 끝났을 때 다음 곡이 이어지는지. 새 곡을 만든 AI 서비스의 약관이 공개 빌드에 쓰는 것을 허용하는지는 사용자가 확인한다.
- **저장 코드 내보내기/불러오기 추가 (2026-10-19)**: 웹 게임의 저장은 플레이어 브라우저 안에만 있고, 게임을 새로 올려서 게임 주소(업로드 번호)가 바뀌면 이전 저장이 사라진다. 실제로 CBT → OBT(0.3.0) 때 테스터 저장이 이어지지 않았다. 그래서 **저장을 글자 코드로 바꿔서 복사해 두었다가 새 버전에서 붙여 넣는 기능**을 로비에 넣었다. 서버나 로그인이 필요 없다.
  - **쓰는 법**: 로비 왼쪽 아래 "테스트 로그" 위의 **"저장 코드"** 버튼 → "코드 복사하기"(또는 "파일로 저장")로 지금 슬롯의 코드를 보관 → 새 버전에서 슬롯을 고르고 같은 창의 "코드 불러오기"를 눌러 코드를 붙여 넣으면 된다. 불러오기 전에 "불러올 저장 / 지금 저장" 요약을 보여 주고 "지금 슬롯의 저장은 사라집니다"를 확인받은 뒤 덮어쓴다.
  - **코드 모양**: `SDSAVE1:` + 저장 내용을 압축(GZip)해서 Base64 글자로 바꾼 것(약 1~2천 자). 압축 안에 검사값이 있어서 중간에 잘리거나 글자가 바뀐 코드는 불러올 때 걸러지고, 비어 있거나 이 게임의 코드가 아니거나 더 새 버전에서 만든 코드도 이유를 알려 주며 거절한다. 테스트 기록 문장(`playLog`)은 코드에 넣지 않는다(너무 길어져서). 기록은 "테스트 로그"로 따로 보내면 된다.
  - **지금 슬롯만**: 코드는 지금 고른 슬롯 하나의 진행 상황(코어·드론·스테이지·천장 등)이다. 불러오면 그 슬롯이 통째로 바뀌고, 덮어쓰기 전 파일은 `.beforeimport`로 한 번 남긴다. 불러온 뒤에는 로비를 다시 불러서 모든 화면이 새 저장으로 바뀐다.
  - **웹에서 붙여넣기가 되는 이유**: 게임 안(유니티)의 입력칸은 웹에서 붙여넣기(Ctrl+V)가 안 되고, 브라우저 기본 `prompt` 창은 itch.io처럼 게임이 다른 페이지 안에 끼워진 경우 막힐 수 있다. 그래서 불러오기를 누르면 **게임 화면 위에 브라우저 입력 창(글상자 + 확인/취소)을 직접 띄운다**(`BrowserBridge.jslib`의 `ShowPasteBox`). 입력 중에는 유니티가 키보드를 가로채지 않게 꺼 둔다.
  - **기록**: 판 기록에 `save_export`(코드를 복사함)·`save_import`(코어=바뀌기 전→바뀐 뒤)가 남는다. 분석기의 "코어 수지 점검"은 `save_import` 줄에서 기준을 다시 잡아서 불러온 직후가 어긋난 줄로 잘못 잡히지 않는다.
  - **검증**: `Verify Save Slots`에 항목을 넣어 전부 통과했다(코드 왕복, 기록 400줄이 있어도 코드는 짧음, 공백·줄바꿈 무시, 비었음/이 게임 코드가 아님/잘림/글자 바뀜/더 새 버전/음수 코어 거절, 슬롯 바꾸기·백업·다른 슬롯 그대로·`DataReplaced` 이벤트, 기록 줄). 에디터 플레이 모드에서 로비 화면으로 복사 → 불러오기 확인 → 덮어쓰기를 시험했고, **실제 WebGL 빌드를 브라우저에서 열어** 같은 흐름(복사한 코드 844자, 입력 창에 붙여 넣고 확인 → 요약 확인 → 덮어쓰기 → 코어가 2,850에서 저장해 둔 2,700으로 돌아옴, 새로고침 뒤에도 유지)을 확인했다.
  - **한계**: 이 기능이 들어 있는 빌드를 처음 올릴 때는 그 전 빌드에서 코드를 못 뽑으므로 저장이 한 번 사라진다. 이후 업데이트부터는 테스터가 코드를 복사해 두었다가 이어서 할 수 있다. 코드는 사람이 값을 고칠 수도 있다(결제가 없는 데모라 막지 않음).
- **아직 안 한 큰 작업**: 3D 모델·텍스처 원본 용량 줄이기(저장소가 약 616MB), 적·구슬 재사용(풀링), WebGL 빌드 설정 점검. WebGL 시험 빌드로 실제 크기와 한글 표시를 확인한 뒤 정한다.

### 안정성(에러 방지) 개선

전체 코드를 한 번 훑어보며 "지금 당장은 문제없지만 나중에 실수하면 게임이 멈출 수 있는 부분"을 찾아 안전장치를 추가했다. 예를 들어 메인메뉴·일시정지·설정·레벨업 화면은 모두 버튼 같은 화면 요소를 이름으로 찾아서 연결하는 방식인데, 나중에 그 이름을 실수로 바꾸거나 지우면 찾기에 실패해서 화면 전체가 멈춰버리는 위험이 있었다. 이제는 못 찾아도 경고 로그만 남기고 나머지 기능은 계속 동작하도록 고쳐뒀다.

| 2026-10-08 | 큰 적에게 밀린 플레이어가 맵 밖으로 튕겨 나가 바닥 아래로 떨어짐 | 보스에게 구석으로 몰린 플레이어가 투명벽을 뚫고 맵 밖으로 나가 끝없이 떨어짐(플레이 모드에서 y −28, −1827까지 관찰). 떨어진 뒤에도 적은 계속 쫓아와 때림 | 보스의 단단한 충돌체가 플레이어(`CharacterController`)를 밀어낼 때, 벽에 이미 붙어 있는 플레이어가 벽 두께를 뚫고 한 번에 몇 미터씩 밀려 나감(투명벽은 얇은 상자 4개뿐이라 이 경우를 막지 못함) | `PlayerController`에 안전장치 `KeepInsideArena` 추가: 이동 직후 플레이어가 맵 범위(±49)를 벗어났거나 바닥 아래(y < −5)로 떨어졌으면 맵 안으로 되돌림(떨어지던 속도도 지움). 평소에는 아무 일도 하지 않고, 되돌릴 때만 콘솔에 `[Player]` 경고를 남김. 플레이 모드에서 (60, −20, −70)으로 강제 이동 → (49, 0, −49)로 복귀, 구석에서 보스 2마리에게 밀리는 상황에서 벽 밖(z −52.1)으로 밀렸다가 −49.0으로 복귀하고 맵 안에 머무는 것을 확인 |
| 2026-10-08 | 저장해 둔 소리 크기가 게임을 다시 켤 때 적용되지 않음 | 설정에서 소리를 줄여 저장했는데, 게임을 다시 켜면 소리가 100%로 크게 들리다가 설정 창을 열면 그때서야 저장한 크기로 돌아옴(웹 빌드와 에디터 모두, 사용자가 발견) | 저장된 볼륨을 적용하는 코드가 `SettingsPanelController`의 `Awake`에만 있었는데, 설정 패널은 씬에서 꺼진 채로 시작해서 패널을 처음 열 때까지 `Awake`가 실행되지 않았음(꺼져 있는 오브젝트의 `Awake`는 켜질 때 처음 실행됨) | `AudioManager`에 `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` 함수를 추가해, 첫 씬이 로드되기 전에 저장된 볼륨을 `AudioListener.volume`에 적용(씬 안 오브젝트에 기대지 않아 어느 씬에서 시작해도 적용). 저장 키는 `AudioManager.MasterVolumeKey`로 합쳐서 두 곳이 같은 키를 쓰게 함. 에디터에서 재현(시작 직후 1.0 → 설정 창을 열면 0.065)한 뒤, 수정 후 시작 직후부터 0.065인 것을 확인 |
