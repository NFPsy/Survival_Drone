# 경제 시뮬레이터 (EconSim)

플레이어가 30일 동안 코어·크레딧을 모으고, 뽑기를 하고, 드론을 강화하면 **SSR을 몇 개 얻고 드론을 얼마나 빨리 다 키우는지**를 컴퓨터로 수천 번 가상 플레이해서 평균을 내 보는 도구입니다. (확률이 들어간 일을 수천~수만 번 반복해서 평균을 보는 방법을 "몬테카를로 시뮬레이션"이라고 부릅니다.)

유니티와 상관없는 **파이썬 도구**라서 게임 파일은 건드리지 않습니다. 파이썬 3.10 이상이 있으면 추가 설치 없이 돌아갑니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `econ_sim.py` | 시뮬레이터 본체. 실행하면 현재 규칙으로 30일 기준선을 출력 |
| `sweep.py` | 규칙 값(소천장·일일 퀘스트·조각 교환·클리어 크레딧)을 바꿔 가며 비교 |
| `validate.py` | 뽑기 로직이 노션 기록(SSR 평균 33.2회, 꽝 10연 18.6% → 0%)과 같은지 확인 |
| `sweep_lock.py` | **아직 게임에 없는** 잠금 리롤(조립 뽑기) 규칙 후보를 비교. "이 규칙으로 넣으면 30일 SSR이 BM 목표(0.5~1.5)를 지키는가"를 구현 전에 미리 계산 |
| `sweep_lock_strategy.py` | 잠금 리롤(조립 뽑기)을 **가장 유리하게 쓰는 플레이어**까지 포함해 검증. 플레이어 전략 3가지(끝까지 채우기 / 첫 공개만 / SSR만 잠그기)와 "잠근 칸만 수령 + 안 가져간 칸 조각 환산" 규칙을 반영 |

## 실행 방법

이 폴더에서 터미널을 열고:

```bash
python econ_sim.py        # 기준선 (인원수를 바꾸려면 python econ_sim.py 10000)
python sweep.py           # 규칙을 바꿔 가며 비교
python validate.py        # 뽑기 로직 검증
python sweep_lock.py      # 잠금 리롤(조립 뽑기) 규칙 후보 비교 (약 40초)
python sweep_lock_strategy.py   # 플레이어 전략별로 조립 뽑기 검증 (약 1분)
```

`sweep_lock.py`의 `lock_share`는 "들어오는 코어 중 조립 뽑기에 쓰는 비율"입니다(0.5 = 절반, 1.0 = 전부). 1.0에서도 목표를 지키면 플레이어가 코어를 어떻게 나눠 쓰든 안전하다는 뜻이라, 1.0을 "최악의 경우(상한)"로 봅니다.

`sweep_lock_strategy.py`의 전략 3가지: **full** = SR 이상을 잠그며 끝까지 채움, **once** = 첫 공개 한 번만 하고 잠글 수 있는 칸만 받은 뒤 다시 시작(300코어씩 반복), **ssr** = SSR만 잠그고 코어가 떨어질 때까지 계속 재뽑기. 칸당 재뽑기 값(100)이 기본 뽑기(300)보다 싸서, 게임을 가장 유리하게 하는 사람(once, ssr)이 "끝까지 채우는 사람"보다 SSR을 더 많이 얻을 수 있습니다. 그래서 BM 목표(30일 SSR 0.5~1.5)는 가장 유리한 전략에서도 지켜지는지로 봅니다.

## 꼭 알아둘 점

1. **규칙 숫자는 손으로 옮겨 적은 것입니다.** `GachaTable`·`DroneGrowthTable`·`CurrencyTable`의 값을 바꾸면 `econ_sim.py` 위쪽 "실제 게임 규칙" 숫자도 같이 고쳐야 합니다. (자동으로 읽어 오지 않습니다.)
2. **플레이어 행동은 실제 데이터가 아니라 가정입니다.** 하루에 몇 판 하는지, 얼마나 자주 접속하는지, 스테이지를 언제 깨는지는 `PROFILES`(max / mid / casual)에 적어 둔 추측입니다. CBT 로그로 실제 값을 알게 되면 거기를 고치세요.
3. 결과는 "퀘스트를 매일 다 받는 최대치" 쪽에 가까우니, 실제 접속·수령 기록으로 보정해서 읽어야 합니다.

## 지표 읽는 법

- `SSR30`: 30일 동안 얻는 SSR 평균 개수 (BM 목표 0.5~1.5)
- `강화30`: 30일 동안 강화한 횟수 (최대 20 = 5종 × 4번)
- `전Lv5중앙일`: 5종 드론이 전부 Lv5가 되는 날(중앙값). **61이면 60일 안에 못 끝낸다는 뜻**
- `크레딧30`: 30일째에 쓰지 못하고 남은 크레딧 (많이 남으면 크레딧 소비처가 부족하다는 신호)
