# 테스트 로그 보관 폴더

테스터가 보낸 로그 원본(.txt)을 모아 두는 곳입니다. **이 README만 깃허브에 올라가고, 로그 파일은 올라가지 않습니다.**
저장소가 공개라서, 테스터 번호·기기 그래픽 정보·플레이 기록이 든 원본은 `.gitignore`로 막아 두었습니다.
(그래서 다른 컴퓨터에는 로그가 없습니다. 그 컴퓨터에서 분석하려면 이 폴더를 복사해 가거나, 노션의 분석 보고서를 보세요.)

## 폴더 구조

| 폴더 | 내용 |
|---|---|
| `cbt/` | CBT 테스터 3명(76E89D=1번, 7956D0=2번, 3DCDAA=3번). **OBT 로그도 여기에 쌓는다** (테스터 번호가 파일 이름에 있어서 구분됨) |
| `dev/` | 개발자 본인 로그(1323F1 = 10/13 본인 CBT, 0A2573 = 10/6~7 초기 빌드). 테스터 분석에 섞이지 않게 따로 둠 |

## 새 로그를 받았을 때 (Claude가 하는 일)

1. 받은 파일을 `cbt/`에 `drone-commander-log-테스터번호-월일-시각.txt` 이름으로 저장한다. (붙여넣은 글이면 같은 형식의 파일로 만든다)
   같은 테스터의 예전 파일은 지우지 않아도 된다. 겹치는 판은 분석기가 한 번만 센다.
2. 폴더 전체를 한 번에 분석한다. (예전 로그를 다시 받을 필요 없음)
3. 노션 "CBT 로그·피드백 분석" 페이지와 "CBT 진행표"에 결과를 갱신한다.

## 분석 명령 (저장소 맨 위 폴더에서)

```bash
python Tools/LogAnalyzer/analyze_logs.py Tools/LogAnalyzer/tester_logs/cbt --out 보고서.md --matches-csv 판목록.csv
```

- 폴더를 주면 그 안의 `.txt`를 전부 읽습니다. 파일을 하나씩 적을 필요가 없습니다.
- `--out`을 생략하면 화면에 출력합니다. 보고서와 CSV는 저장소 밖(바탕화면 등)에 저장하세요. 테스터 번호가 들어 있어서 저장소에 두지 않는 편이 좋습니다.
- 개발자 로그까지 같이 보고 싶으면 `Tools/LogAnalyzer/tester_logs` 폴더를 통째로 주면 됩니다.
