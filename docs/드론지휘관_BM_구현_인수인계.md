# 드론 지휘관 — 가챠 BM 레이어 구현 인수인계 (2026-09-29 대화 정리)

> 이 문서는 Claude 채팅(Cowork)에서 9/29에 나눈 기획 대화를 정리한 것이다. **구현은 Code 탭에서 이어서 진행**한다. 이 문서만 읽어도 무엇을 왜 만드는지, 어디까지 정해졌고 무엇이 열려 있는지 알 수 있게 썼다.
> 각 항목에 **[확정]** / **[초안]** / **[미정]** 표시를 붙였다. [초안]은 제가 임의로 잡은 값이라 바꿔도 된다. [미정]은 구현 전에 사용자(서연)에게 물어볼 것.

## 0. 한 줄 요약

기존 뱀서라이크 드론 게임(Unity)에 **"판 사이의 메타 루프(재화 → 뽑기 → 드론 장착·강화 → 더 강한 스테이지)"와 가챠 BM**을 얹는다. 목적은 **게임 기획자 포트폴리오**이고, 핵심은 BM 설계(재화 흐름·확률·천장·과금 유형별 성장)와 그 검증이다. 실제 결제는 구현하지 않는다.

## 2. 대화에서 내린 결정 [확정]

1. 후보 4개(드론 게임 다듬기 / 삼국지 카드덱 / 삼국지 가챠 / 새 게임) 중 **드론 게임 + BM 레이어**로 확정. 이유: 코어 루프가 이미 플레이 가능해서 남은 시간을 전부 BM 설계에 쓸 수 있고, 뱀서라이크 + 가챠 성장은 상업적으로 검증된 구조(Survivor.io, Archero 등). 삼국지 쪽은 아트 부담과 경쟁 포트폴리오가 많아 제외.
2. 기존 게임 확장이 프로젝트로 인정되는지는 사용자가 "상관없다"고 했다.
3. **"보통 게임에 없는 재미 요소" 1~2개**:
   - ① 오버드라이브 (이미 구현됨): 이득이 큰 순간이 곧 가장 위험한 순간. 5초간 공속 2.5배·이동 +25%, 받는 피해 2배(회복 드론 제외).
   - ② **잠금 리롤 가챠** (신규, CBT 초반에 추가): 뽑기 1회에 3슬롯이 공개되고, 마음에 드는 슬롯을 잠근 뒤 나머지만 재뽑기. 잠글수록 재뽑기 단가가 오른다.
4. 실제 결제는 구현하지 않는다. 가상 재화 상점 UI는 OBT에 UI만. 확률·천장은 **UI에 상시 공개**한다.
5. 산출물(이미 만들어 둠, 아래 §9): 시뮬레이터 엑셀, 화면 구성안 pptx, BM 설계서 pptx.

## 4. 가챠 규칙

### 4.1 기본 뽑기 (MVP)
- 대상: **드론** (드론 5종 × 등급 4단계)
- 등급 확률 **[확정]**: N 55.0% / R 30.0% / SR 12.5% / SSR 2.5% (합 100%)
- 비용: 1회 300코어, 10연 2,700코어 (9회 가격, 10% 할인)
- **천장 70회 하드 천장 [확정]**: 누적 70회째 뽑기에서 SSR 확정. SSR을 얻으면 카운트를 0으로 초기화. (천장 카운터는 뽑기 1회마다 +1, 10연은 10번 순차 처리)
- 중복: **조각**으로 환산해 영구 강화에 사용. 등급별 환산 수치 **[미정]** (화면 구성안에는 "중복 +30 조각"이 예시로만 나옴)
- 신규 획득은 NEW 표시

### 4.2 잠금 리롤 = "조립 뽑기" (CBT에서 추가)
- 1회(300코어)에 **3슬롯 동시 공개**. 성공 슬롯(목표 등급 이상)을 잠그고 나머지만 재뽑기.
- **재뽑기 비용 = 남은 슬롯 수 × 100 × (1 + 프리미엄 × 잠근 슬롯 수)**, 프리미엄 기본 0.5 [초안]
  - 잠금 0개: 3×100 = 300 / 잠금 1개: 2×100×1.5 = 300 / 잠금 2개: 1×100×2.0 = 200
- 슬롯의 게임 내 의미 **[미정]**: 화면 구성안은 "슬롯 1 본체 / 슬롯 2 코어 / 슬롯 3 펌웨어"를 예시로 그렸다. CBT 초반에 확정.
- 검증용 기대값(단위 테스트에 쓸 수 있음): 슬롯 성공 확률 q = 0.15(SR 이상), 성공 슬롯은 항상 잠그는 전략일 때 **3슬롯 전부 SR 이상이 될 기대 비용 = 2,918.9코어**(프리미엄 0.5). 잠금 없이 통째로 뽑으면 88,888.9코어.

## 6. 스테이지 / 성장 벽 [초안]

가챠가 의미 있으려면 "뽑은 만큼 강해져야 넘을 수 있는 벽"이 필요하다. 삭제한 난이도 3단계를 **스테이지형 배율**로 대체한다.

| 스테이지 | 이름 [초안] | 권장 전투력 | 적 체력 배율 |
|---|---|---|---|
| 1 | 외곽 순찰로 | 100 | ×1.0 |
| 2 | 폐공장 지대 | 220 | ×1.5 |
| 3 | 중앙 관제탑 | 400 | ×2.2 |

- 이전 스테이지 클리어 시 다음 스테이지 해금
- **배율은 적 체력·접촉 피해에만 곱한다. 스폰 속도·최대 마릿수는 그대로.** (9/8 교훈: 적을 줄이면 XP 구슬도 줄어 레벨업이 오히려 느려짐)
- 전투력 = 장착 드론의 등급·레벨 합산 수치 (공식 **[미정]**). 권장 대비 색: 100% 이상 초록 / 70~100% 주황 / 70% 미만 빨강
- 최초 클리어 보너스는 검토안 (시뮬레이터 미반영)

(현재는 메인 메뉴 "게임 시작"이 바로 InGame으로 간다. 이걸 로비 경유로 바꾼다. 난이도 팝업은 이미 삭제됨.)

**공통 UI 규칙**: 색 의미는 기존 체계 유지 — 시안 = 성장/성공/주요 버튼, 빨강 = 피해/경고/GAME OVER, **주황 = 선택한 위험(오버드라이브, 잠금 프리미엄)**, 금색 = SSR/천장. 등급색 N 회색 / R 파랑 / SR 보라 / SSR 금색. 버튼 상태 3종: 활성(시안 채움) / 비활성(회색) / 재화 부족(가격 글자만 빨강, 탭하면 "코어가 부족합니다" 팝업). 천 단위 콤마, 재화 증가는 카운트업.

**"표기 = 실제" 원칙 (중요)**: 확률표 UI는 뽑기 로직이 쓰는 데이터 파일(`GachaTable`)의 값을 그대로 읽어 자동 생성한다. 표기용 숫자를 따로 적지 않는다. (9/6 버그 교훈: 씬·프리팹에 저장된 값이 코드 기본값을 덮어써서 밸런스가 반영 안 된 적이 있음. 값의 출처를 한 곳으로.)

### 8.2 뽑기 로직 요구사항

- 난수는 서버 없이 클라이언트 `System.Random` 또는 `UnityEngine.Random` 사용 (단, 테스트에서 시드 고정 가능하게 주입).
- 뽑기 1회 처리: `pity += 1` → `pity >= 70`이면 SSR 확정, 아니면 확률표로 굴림 → SSR이면 `pity = 0`.
- 10연은 위 처리를 순차 10번. 코어 차감은 2,700을 먼저 확인 후 한 번에.
- 코어 부족 시 차감·뽑기 모두 하지 않고 "부족" 이벤트만 발생.
- 결과 객체에 등급·드론 종류·신규/중복 여부·조각 환산량을 담아 UI로 전달.
- 확률·비용·천장은 전부 `GachaTable`에서 읽는다. 코드 상수로 박지 말 것.

### 8.4 구현 시 지킬 프로젝트 관례 (README에서 가져옴)

- 밸런스 수치를 바꾸면 README의 **밸런스 조정 기록 표**(날짜·항목·변경 전→후·파일·이유)에 남긴다. 버그는 **버그 수정 내역 표**(증상·원인·해결)에 남긴다. 이 기록이 포트폴리오 자산이다.
- 플레이 로그를 콘솔에 남긴다(승패, 뽑기 결과, 재화 수지). Unity 콘솔 Collapse에 묻히지 않도록 매번 문구가 달라지게(수치·시간 포함). **CBT 로그가 시뮬레이터 보정의 근거**이므로 뽑기 횟수·재화 수지·판당 코어·스테이지 클리어율은 파일(CSV/JSON)로도 남기면 좋다.
- 화면 요소를 이름으로 찾아 연결하는 코드는 못 찾아도 경고 로그만 남기고 계속 동작하게 (기존 안정성 개선 방식).
- 씬/프리팹 인스펙터 값이 코드 기본값을 덮어쓴다 → 수치는 ScriptableObject에 두고 씬/프리팹에 중복 저장하지 않기.
- Unity MCP를 써서 씬·프리팹 값을 직접 수정한 이력이 있다(9/6).

## 10. 아직 정하지 않은 것 [미정] — 구현 전에 서연에게 확인

1. 중복 시 **조각 환산 수치** (등급별) 와 강화에 필요한 조각 수
2. **크레딧 경제** (판 보상 획득량, 드론 강화 비용, 강화 시 스탯 상승률)
3. **조립 뽑기 슬롯의 게임 내 의미** (본체/코어/펌웨어는 예시일 뿐) — CBT 전에 확정
4. **출격 시 장착 드론 개수** (초안 2개) 와 전투력 계산 공식
5. 뽑기로 얻는 드론 5종의 **등급별 성능 차이**(등급이 인게임 성능에 어떻게 반영되는지). 기존 드론 성장률은 레벨당 16%, 5레벨 변신 ×1.2
6. 코어 칩이 오버드라이브를 바꾸는 아이디어는 "검토" 상태 (MVP 범위 아님)

## 11. 알려진 한계 (시뮬레이터)

- 확률·천장·코어 가격(1코어=10원)·월정액은 시장 관행을 참고한 **설계 초안용 가정**이다. 실제 시장 데이터나 사용자가 준 수치가 아니다.
- 기대 SSR 수는 "누적 뽑기 횟수 ÷ 천장 반영 기대 뽑기 수(33.2)"로 근사한 값이다.
- 클리어율은 유형별 고정값이다. 뽑기로 강해져서 클리어율이 오르는 피드백은 반영하지 않았다 (CBT 로그로 보정).
- 크레딧 경제는 모델링하지 않았다.
